# Quick Task 260901-g0s: OpenSky empty result is a measured zero, not a failure

## Problem

`opensky.aggregator.ts` treats an empty flight list as `{ ok: false, reason: 'no_data' }`.
An empty result set is a successful measurement whose value is zero, not a failed fetch.

Consequence in the scoring engine: an airport with genuinely zero traffic loses its
`volume` component (`resolveVolume` needs `movements.ok`) **and** its `headroom` component
(`resolveHeadroom` needs `movements.ok`). `scoreAirports` then reweights onto the single
surviving component, and `minMaxNormalize` over a one-element dataset returns 50 — so a
dead airport scores 50 and can outrank a busy airport that was measured properly.

The correct modelling gives it `passengerMovements: 0`, which is the dataset minimum, which
normalizes to 0 — sinking it to the bottom of the ranking, which is the true answer.

## Evidence

OpenSky documents 404 as an empty result set, not a missing resource
(https://openskynetwork.github.io/opensky-api/rest.html):

> "If no flights are found for the given period, HTTP stats 404 - Not found is returned
> with an empty response body."

So `opensky.client.ts`'s `404 -> []` is correct — it decodes a documented non-standard
dialect at the adapter boundary, which is what an adapter is for. The line was only ever
missing its citation. The defect is one layer down, where the aggregator translates that
`[]` back into a failure.

The same repo already models this correctly in `nasStatus.ts`: an airport with no delay
events returns `{ ok: true, data: { events: [] } }`.

## Rule established

**The HTTP status decides success or failure. The payload's contents never do.**

## Tasks

### Task 1 — Cite the 404 decoding

**Files:** `src/domain/adapters/opensky.client.ts`

**Action:** Keep `if (response.status === 404) return [];` and add a comment citing the
OpenSky doc, so the next reader does not mistake it for a swallowed error.

**Verify:** `npx tsc --noEmit`

**Done:** The line states why 404 is a result and not a failure.

### Task 2 — Stop treating an empty list as a failure

**Files:** `src/domain/adapters/opensky.aggregator.ts`

**Action:** Delete the `no_data` branch. Cascading cleanups that follow from the deletion:
- `departureCount` / `arrivalCount` locals existed for that condition and are now
  single-use — inline them into the `Movements` literal.
- `| undefined` param types and the `|| []` guards are now unreachable — tighten to
  required arrays.
- The `as AdapterResult<Movements>` cast goes with the line that held it.

**Verify:** `npx tsc --noEmit`

**Done:** `aggregateMovements` returns `ok: true` for any successfully fetched window,
including an empty one.

### Task 3 — Retarget the test that locked the old modelling

**Files:** `src/domain/adapters/opensky.test.ts`

**Action:** Replace `'empty window (both legs 404) returns no_data'` with a test asserting
`ok: true` and zero counts. Leave `'treats a single 404 leg as a legitimate zero'`
unchanged — it now holds for both legs too.

**Verify:** `npx vitest run`

**Done:** 122 tests pass, same count as before.

## Out of scope

- `'no_data'` stays in `AdapterFailReason` — still used correctly by `faaFacility.ts:42`
  (ICAO absent from the FAA registry, so there is no `FaaFacility` to return) and by
  `headroomReason` in `expansionScore.ts:103` (a derived label, not a fetch failure).
- Narrowing `aggregateMovements`'s return type to `Movements` now that it cannot fail.
  Doing so requires moving the `AdapterResult` wrap into `opensky.ts` **inside** the
  `withCache` callback, or `fetchedAt` would be recomputed on every cache hit and claim a
  freshness the data does not have. Separate change.

## Downstream safety

Checked before planning — no division by zero on a zero-movement `Movements`:

| Consumer | Behaviour with zero movements |
|---|---|
| `computeVolumeKpi` | counting only → all zeros |
| `computeHeadroomKpi` | already wraps `runwayCount` in `Math.max(1, ...)`; `0 / N = 0` |
| `computeDelayKpi` | does not read movements |
| `flightDestinationsTool` | map/filter only → `destinations: []`, `totalDepartures: 0` |
