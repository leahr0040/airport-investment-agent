<objective>
Fix WR-01 from `.planning/phases/02-live-data-adapters-caching/02-REVIEW.md`: two independent in-flight-request races that let concurrent callers each become a "miss" and duplicate an upstream call. `withCache` (`src/domain/adapters/cache.ts`) checks `cache.has(key)` synchronously and only writes back via `cache.set(...)` after `await fn()` resolves, so two concurrent calls for the same key both see a miss. `OpenSkyClient.ensureToken()` (`src/domain/adapters/opensky.client.ts`) has the identical shape: two concurrent callers before the first token request resolves each POST to the OAuth token endpoint.

Purpose: the project's OpenSky quota (400-4,000 credits/day) is a hard budget explicitly protected by caching and rate-limiting per CLAUDE.md; an unguarded in-flight race silently defeats part of that protection under any real concurrency (e.g. a region query fanning out `Promise.all` across several airports, or two chat turns referencing the same airport).

Output: `withCache` rewritten to use the installed `lru-cache@11.5.2`'s native `cache.fetch(key, { fetchMethod, ttl })`, which natively single-flights concurrent fetches for the same key, replacing the manual has/set race entirely (no hand-rolled `Map`-based in-flight tracker). `OpenSkyClient` gets a `pendingTokenRequest` field that memoizes the in-flight token promise. Both fixes are covered by new concurrency regression tests; all pre-existing tests in both files continue to pass unchanged.
</objective>

Replace the manual `cache.has(key)` / `await fn()` / `cache.set(...)` sequence in `withCache` (`src/domain/adapters/cache.ts`, current lines 23-38) with a single call to the underlying `LRUCache` instance's native `cache.fetch(key, options)` method — already available on the installed `lru-cache@11.5.2` (`node_modules/lru-cache/package.json` confirms this version; no dependency change needed). Pass `{ ttl: ttlMs, fetchMethod: async () => { ... } }` as `options`, so each call's own `ttlMs` argument still governs that key's expiry exactly as it does today via `cache.set`'s `{ ttl: ttlMs }`.

Inside `fetchMethod`: set a `let missed = false` local variable (scoped per `withCache` invocation) to `true`, increment the existing module-level `misses` counter, call the caller's `fn()`, and return its resolved value mapped through the existing `UNDEFINED_VALUE` sentinel (`value === undefined ? UNDEFINED_VALUE : value`) exactly as the current code does before `cache.set`. This sentinel mapping is required because lru-cache's `fetch()` treats a `fetchMethod` that resolves to a bare `undefined` as "do not cache this value" — without the sentinel, the existing "supports a producer that resolves to undefined" test would stop caching and re-invoke `fn()` on every call.

`fetchMethod` is only invoked by lru-cache when the entry is absent or stale, and lru-cache's `fetch()` natively tracks one in-flight promise per key internally — a second `cache.fetch()` call for the same key made before the first's `fetchMethod` resolves joins that same in-flight promise instead of starting its own. This native tracking is the mechanism that replaces the manual has()/set() race; do not add a hand-rolled `Map`-based in-flight tracker alongside it.

After `await cache.fetch(key, options)` resolves, increment the module-level `hits` counter only when the local `missed` flag is still `false` — meaning lru-cache served the call without invoking this call's `fetchMethod`, either because a fresh entry already existed or because a concurrent in-flight fetch for the same key was already running and this call joined it. Unwrap the `UNDEFINED_VALUE` sentinel on the way out exactly as the current code does, and return the unwrapped value cast to `T`.

If `fn()` rejects inside `fetchMethod`, let the rejection propagate — do not catch it. lru-cache's `fetch()` rejects when `fetchMethod` rejects and, by default, does not cache the rejected result, matching the existing "propagates a rejected producer and does not cache its failure" test.

Leave `UNDEFINED_VALUE`, the module-level `hits`/`misses` counters, `getCacheStats()`, and `clearCache()` completely untouched. `withCache<T>(key: string, ttlMs: number, fn: () => Promise<T>): Promise<T>`'s exported signature must not change — `faaFacility.ts`, `nasStatus.client.ts`, and `opensky.ts` (its three existing callers) require zero changes.

In `cache.test.ts`, add one new `it` block inside the `describe('withCache', ...)` block (after the existing "supports a producer that resolves to undefined" test): build `producer = vi.fn().mockResolvedValue({ value: 'shared' })`, call `Promise.all([withCache('concurrent-key', 60_000, producer), withCache('concurrent-key', 60_000, producer)])`, await the result, and assert both resolved entries deep-equal `{ value: 'shared' }` and that `producer` was called exactly once (`toHaveBeenCalledTimes(1)`).
