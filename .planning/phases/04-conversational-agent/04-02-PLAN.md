<objective>
Close three of the four gaps found by 04-VERIFICATION.md (2026-08-19): QUERY-03 (long-haul flight share), QUERY-04 (runway-separation-based unmet-demand cause), and QUERY-05 (universal assumptions/data-window/proxy disclosure). CHAT-02 (structured score rendering independent of LLM prose) is explicitly out of scope per 04-CONTEXT.md's user decision and is not touched by this plan.

This phase already shipped a working chat agent (04-PLAN.md/04-SUMMARY.md): Gemini native tool-calling over `resolve_region`/`score_airports`, session memory, rate limiting, and a deterministic scoring engine the LLM can never bypass. This plan adds two new tools that expose real, already-fetched upstream data (OpenSky per-flight destinations; FAA runway geometry and NAS delay events) that no tool currently surfaces, threads a discarded data-window field through the existing scoring path, and extends SYSTEM_PROMPT to require the agent to disclose data windows, proxy status, and — for the two new tools — that any distance or separation judgment it states is its own estimate, not a code-computed value. Per explicit user decision (04-CONTEXT.md), no deterministic distance/geometry computation is added anywhere; the agent reasons over real coordinates and codes itself.

Purpose: make the three failed Success-Criterion sub-clauses genuinely answerable from real data, with the model required to state its assumptions honestly, while preserving the project's core value that every *number* the agent states is traceable to a deterministic computation — the LLM only makes the judgment calls (distance, grouping) that were explicitly scoped out of the deterministic core.

Output: two new tools (`flight_destinations`, `runway_conditions`) wired into the existing `TOOL_DECLARATIONS`/`TOOL_HANDLERS` pattern; `VolumeKpi` carrying its data window and a proxy disclosure; an extended, exported `SYSTEM_PROMPT` requiring disclosure of window, proxy status, and estimate provenance.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Upstream FAA NAS Status XML (`NasStatusEvent.reason`/`.raw`/`.type`) -> `runway_conditions` tool result -> Gemini LLM context | Untrusted third-party free text crossing into LLM context — the exact SEC-04 boundary this plan must not regress. |
| Upstream OpenSky-inferred `estArrivalAirport` strings -> `flight_destinations` tool result -> Gemini LLM context | Untrusted upstream-inferred identifier strings crossing into LLM context. |
| LLM-supplied `icaos` tool-call args -> outbound FAA ArcGIS / FAA NAS Status / OpenSky URLs | LLM/analyst-influenced input reaching an outbound HTTP call keyed by airport code. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | `runwayConditionsTool` delay-event projection (`tools.ts`) | high | mitigate | Never forward `NasStatusEvent.reason`/`.raw`; reduce `.type` via the fixed-enum `classifyDelayType` classifier (keyword match, never echoes the raw string); sanitize `.start`/`.reopen` via the `sanitizeTimestampLike` regex allowlist. Preserves the existing SEC-04 guarantee that no raw upstream text reaches the LLM, extended to the new tool. |
| T-04-02 | Tampering | `flightDestinationsTool` destinations projection (`tools.ts`) | medium | mitigate | `estArrivalAirport` values are filtered through `isValidIcao` before inclusion; malformed or unexpected upstream strings are dropped, never passed through verbatim. |
| T-04-03 | Spoofing (prompt injection via tool-result content) | Gemini `functionResponse` parts carrying tool results (`google.ts`) | low | accept | Tool results are returned as `functionResponse` data parts, not natural-language instructions, per the existing (SEC-04-satisfied) architecture; T-04-01/T-04-02 further reduce what upstream text could even reach this boundary. |
| T-04-04 | Tampering (malformed identifier reaching an outbound call) | `icaos` args on the two new tools reaching `fetchFaaFacility`/`fetchNasStatus`/`fetchMovements` | medium | accept | Each adapter already gates its own outbound call behind `isValidIcao(icao)` (pre-existing, unmodified by this plan) — a malformed code from either new tool short-circuits to `{ok:false, reason:'invalid_input'}` before any URL is built. |
