    - Two withCache calls with different keys invoke the producer twice.
    - After advancing fake timers past the TTL, a third call with the original key invokes the producer again (3rd invocation total).
    - A shorter TTL entry expires while a longer TTL entry set at the same moment is still served from cache — proving per-entry TTL, which is what DATA-04's per-source TTLs rest on.
    - A producer that rejects propagates the rejection to the caller AND leaves nothing cached: a subsequent call with the same key invokes the producer again. Failures are never cached (D-06 hard-fail: a transient upstream error must not be pinned for the whole TTL).
    - getCacheStats() reports misses incrementing on a cold key and hits incrementing on a warm key.
    - clearCache() empties the store and zeroes the stats.
  </behavior>
  <action>
Create `src/domain/adapters/cache.ts` exporting a generic cache-aside wrapper over a single module-level `LRUCache` instance.

Exports:
- `withCache<T>(key: string, ttlMs: number, fn: () => Promise<T>): Promise<T>` — on a hit, return the cached value cast to `T` without calling `fn`; on a miss, await `fn()`, store the resolved value with the per-call TTL via the cache's per-entry ttl option, and return it. If `fn` rejects, let the rejection propagate and store nothing.
- `getCacheStats(): { hits: number; misses: number; size: number }` — module-level counters plus the live entry count. This is what makes DATA-04's "no duplicate upstream call" claim directly assertable in tests and in plan 02-05's live smoke run, rather than inferred from timing.
- `clearCache(): void` — empties the store and resets the counters. Used by tests and by the smoke run; harmless in production.

Construct the `LRUCache` with `max: 2000` and no construction-time default `ttl` — every caller passes its own TTL, so a construction default would silently apply to any caller that forgot one. Leave `updateAgeOnGet` at its default of false: a cached value must expire on a fixed schedule matching its source's volatility, not have its clock reset because someone asked about the same airport again.

Distinguish a cached `undefined` from a miss by checking membership rather than truthiness of the returned value — use the cache's `has(key)` before `get(key)`, so a producer that legitimately resolves to `undefined` is not re-run on every call. Type the instance value as `unknown` and cast on read.

Do not add request coalescing, disk persistence, or a background sweeper — D-02 accepts a memory-only cache that empties on restart, and concurrent duplicate in-flight requests are out of scope for a single-analyst demo.

Export two named TTL constants for the adapters to import so the per-source values live in one inspectable place rather than being repeated as literals at call sites: `OPENSKY_TTL_MS` = 5 minutes in milliseconds and `NAS_STATUS_TTL_MS` = 3 minutes in milliseconds. Both sit inside D-03's accepted ranges (OpenSky 5–10 min, NAS 2–5 min). Also export `OPENSKY_BUCKET_SECONDS` = 300 so plan 02-03's window bucketing and the OpenSky TTL provably use the same period.

Write `src/domain/adapters/cache.test.ts` first, covering every case in the behavior block, using `vi.useFakeTimers()` / `vi.advanceTimersByTime()` for the expiry cases and `vi.fn()` producers with `toHaveBeenCalledTimes` assertions for the invocation counts. Call `clearCache()` in `beforeEach`. Restore real timers in `afterEach`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → adapter input | Airport identifiers reaching this layer originate upstream from analyst text (Phase 4 LLM extraction) and are untrusted until format-checked. `validate.ts` is that checkpoint. |
| process environment → module scope | `src/config/env.ts` holds OpenSky credentials; the test harness must not weaken the boundary that keeps them out of client bundles. |
| in-process cache → future readers | Values held in `withCache` are returned unvalidated to whichever tier reads them later. |
